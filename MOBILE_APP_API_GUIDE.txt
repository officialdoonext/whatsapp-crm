1. ARCHITECTURE & MOBILE INTEGRATION STRATEGY
================================================================================

1.1 THE TWO API INTEGRATION OPTIONS FOR MOBILE

Your web CRM utilizes a hybrid architecture:
  A. Supabase (PostgreSQL + Auth + Storage + Realtime): Directly handles 90% of
     all database queries (Reads, Inserts, Updates, Deletes) using Row Level
     Security (RLS).
  B. Next.js Server API Routes: Handles sensitive third-party interactions that
     require server secrets (Meta WhatsApp Cloud API sending, AI generation,
     encryption, rate limiting).
  C. Public REST API (/api/v1): Headless API authenticated with API Keys
     (Bearer wacrm_live_...), useful for integrations.

RECOMMENDED MOBILE APP ARCHITECTURE (Option A + B):
  - Use the official Supabase Client SDK for your mobile framework:
    * React Native: @supabase/supabase-js
    * Flutter: supabase_flutter
    * Swift (iOS): Supabase-Swift
    * Kotlin (Android): supabase-kt
  - Mobile user signs in with email/password via Supabase Auth.
  - The mobile app performs direct reads/writes for Contacts, Notes, Deals,
    Pipelines, Tags, and Notifications via Supabase client.
  - Supabase Realtime delivers instantaneous chat messages, reactions, and badges.
  - For sending WhatsApp messages, media uploads, and AI drafting, the mobile app
    calls your Next.js backend API routes passing the Supabase Auth session token.


1.2 MOBILE AUTHENTICATION & SESSION LIFECYCLE

Step 1: Sign in user
  Method: supabase.auth.signInWithPassword({ email, password })
  Response returns: session.access_token (JWT), session.refresh_token, user.id.

Step 2: Fetch user profile & tenancy
  Query:
    const { data: profile } = await supabase
      .from('profiles')
      .select('id, full_name, email, avatar_url, account_id, account_role, status, expiry_date')
      .eq('user_id', session.user.id)
      .single();

  Store in mobile local state / secure storage:
    - account_id  : The tenant ID for all operations
    - account_role: 'owner' | 'admin' | 'agent' | 'viewer'
    - status      : Must be 'active' to access data

Step 3: Authenticating API requests to your Next.js backend
  When calling Next.js routes (like /api/whatsapp/send):
  Pass the user's Supabase JWT access token in the headers:
    Authorization: Bearer <session.access_token>
  Or configure your mobile HTTP client to pass Supabase cookie headers.


1.3 ROW-LEVEL SECURITY (RLS) IN MOBILE

- Every table in PostgreSQL has RLS enabled.
- Queries executed through the Supabase Mobile SDK automatically apply the
  caller's `auth.uid()` and filter data exclusively to the caller's `account_id`.
- You never need to worry about one company/account seeing another company's data.


1.4 SUPABASE REALTIME WEBSOCKETS

- Enables live WhatsApp chat without polling.
- Mobile connects to Supabase Realtime using WebSocket.
- Handled via `supabase.channel(...)` listeners on table changes (`INSERT`, `UPDATE`, `DELETE`).


1.5 SUPABASE STORAGE (MEDIA ATTACHMENTS)

- Bucket Name: `chat-media` (Public bucket)
- Path convention required by RLS:
    account-<account_id>/<timestamp>-<sanitized_file_name>.<ext>
- Upload file binary directly to Supabase Storage, retrieve the Public URL,
  and supply `media_url` to the WhatsApp send endpoint.


1.6 META WHATSAPP 24-HOUR CUSTOMER SESSION WINDOW

- WhatsApp Business Cloud API Policy:
  When a customer sends a message, a 24-hour service window opens.
  * Within 24 hours: Agents can send free-form text, images, videos, audio, documents.
  * After 24 hours: Free-form messages are REJECTED by Meta. You can ONLY send
    pre-approved Meta Message Templates.
- Mobile implementation rule:
  Calculate: difference in hours between `now()` and the last customer message's `created_at`.
  If >= 24 hours, disable standard text input and display a button:
  "24h session expired. Send a Template to re-open conversation".

2.2 SCREEN 2: DASHBOARD / ANALYTICS OVERVIEW
--------------------------------------------------------------------------------
Features on Screen:
  - Metric Card 1: Active Conversations (Count of open conversations vs yesterday)
  - Metric Card 2: New Contacts Today (Count of contacts created today vs yesterday)
  - Metric Card 3: Open Deals Value & Count (Sum of open deal values + deal count)
  - Metric Card 4: Messages Sent Today (Count of agent messages sent today vs yesterday)
  - Volume Trend Chart: Inbound vs Outbound messages (7 / 30 / 90 days filter)
  - Pipeline Funnel / Donut: Total value and count grouped by pipeline stage
  - Response Time: Average & median first-response time in minutes
  - Activity Feed: List of recent events (messages, deals won, contacts created)

HOW TO FETCH / READ DASHBOARD DATA:

1. Metric Cards:
   Run parallel Supabase counts:
   const todayStart = new Date();
   todayStart.setHours(0,0,0,0);
   const todayIso = todayStart.toISOString();

   // Active Conversations:
   supabase.from('conversations').select('id', { count: 'exact', head: true }).eq('status', 'open')

   // New Contacts Today:
   supabase.from('contacts').select('id', { count: 'exact', head: true }).gte('created_at', todayIso)

   // Open Deals Value:
   const { data: deals } = await supabase.from('deals').select('value, status').eq('status', 'open');
   const totalValue = deals.reduce((acc, curr) => acc + (curr.value || 0), 0);

   // Messages Sent Today:
   supabase.from('messages').select('id', { count: 'exact', head: true }).eq('sender_type', 'agent').gte('created_at', todayIso)

2. Pipeline Funnel Breakdown:
   Query deals with pipeline stages:
     const { data: stages } = await supabase
       .from('pipeline_stages')
       .select('id, name, color, position')
       .order('position', { ascending: true });

     const { data: openDeals } = await supabase
       .from('deals')
       .select('stage_id, value')
       .eq('status', 'open');

     Aggregate on mobile: Group deals by `stage_id`, calculate count and sum(value).

3. Recent Activity Feed:
   Query the latest 30 messages and deals:
     const { data: recentMessages } = await supabase
       .from('messages')
       .select('id, sender_type, content_text, created_at, conversation:conversations(contact:contacts(name, phone))')
       .order('created_at', { ascending: false })
       .limit(20);

HOW TO FETCH / READ CONVERSATIONS:

Query:

    .from('conversations')
    .select(`
      id,
      status,
      assigned_agent_id,
      last_message_text,
      last_message_at,
      unread_count,
      ai_autoreply_disabled,
      ai_reply_count,
      created_at,
      updated_at,
      contact:contacts (
        id,
        name,
        phone,
        wa_username,
        avatar_url,
        company,
        contact_tags (
          tag:tags ( id, name, color )
        )
      )
    `)
    .order('last_message_at', { ascending: false });

  // Filter by status tab:
  if (statusFilter !== 'all') {
    query = query.eq('status', statusFilter); // 'open' | 'pending' | 'closed'
  }

  // Filter by assigned agent:
  if (assignedFilter === 'me') {
    query = query.eq('assigned_agent_id', currentUserId);
  } else if (assignedFilter === 'unassigned') {
    query = query.is('assigned_agent_id', null);
  }

REALTIME SUBSCRIPTION FOR CONVERSATION LIST:
  Subscribe to table `conversations`:
    const channel = supabase
      .channel('public:conversations')
      .on('postgres_changes', {
        event: '*',
        schema: 'public',
        table: 'conversations',
      }, (payload) => {
        if (payload.eventType === 'INSERT') {
          // New conversation arrived: fetch full joined row and prepend to list
          fetchSingleConversation(payload.new.id);
        } else if (payload.eventType === 'UPDATE') {
          // Update last_message_text, last_message_at, unread_count, status
          updateConversationInState(payload.new);
        }
      })
      .subscribe();

HOW TO FETCH CONTACTS (WITH PAGINATION & SEARCH):

Query (Standard):
  const PAGE_SIZE = 25;
  const from = page * PAGE_SIZE;
  const to = from + PAGE_SIZE - 1;

  let query = supabase
    .from('contacts')
    .select('*, contact_tags(tag:tags(*))', { count: 'exact' })
    .order('created_at', { ascending: false })
    .range(from, to);

  if (searchTerm.trim()) {
    const like = `%${searchTerm.trim()}%`;
    query = query.or(`name.ilike.${like},phone.ilike.${like},email.ilike.${like}`);
  }

  const { data: contacts, count, error } = await query;

Query (Filtered by Tag IDs):
  Call PostgreSQL RPC function `filter_contacts_by_tags`:
  const { data, error } = await supabase.rpc('filter_contacts_by_tags', {
    p_tag_ids: selectedTagIds,
    p_search: searchTerm || null,
    p_limit: PAGE_SIZE,
    p_offset: from,
  });

CREATE CONTACT:

    const { data: newContact, error } = await supabase

UPDATE CONTACT:

START CONVERSATION FROM CONTACT:

  1. Check if a conversation already exists:

       .from('conversations')
       .select('id')
       .eq('contact_id', contactId)

4. REALTIME EVENT SUBSCRIPTION MATRIX
================================================================================

To give your mobile app instant, WhatsApp-like responsiveness, establish
these Supabase Realtime channels:

Channel 1: `global:conversations`
  Table: `conversations`
  Events: `INSERT`, `UPDATE`
  Mobile Action: Updates conversation list, unread badge counters, last message.

Channel 2: `thread:<conversation_id>` (Subscribed only when chat thread is active)
  Table: `messages`
  Filter: `conversation_id=eq.<active_id>`
  Events:
    - `INSERT`: Appends new customer or agent message to chat bubble list.
    - `UPDATE`: Updates ticks (sent -> delivered -> read) or marks failed.

Channel 3: `reactions:<conversation_id>`
  Table: `message_reactions`
  Filter: `conversation_id=eq.<active_id>`
  Events: `INSERT`, `DELETE`
  Mobile Action: Renders or removes emoji reaction below chat bubble.

Channel 4: `notifications:<account_id>`
  Table: `notifications`
  Filter: `account_id=eq.<account_id>`
  Events: `INSERT`
  Mobile Action: Triggers system push notification and header bell badge.

5. ERROR CODES & EDGE CASES REFERENCE
================================================================================

1. HTTP 400 Bad Request (`bad_request`)
   - Reason: Phone number missing leading `+` or country code.
   - Solution: Mobile app must validate and format numbers to E.164 (e.g. `+14155552671`).

2. HTTP 401 Unauthorized (`unauthorized`)
   - Reason: Expired Supabase session or invalid token.
   - Solution: Call `supabase.auth.refreshSession()` or redirect to Login screen.

3. HTTP 403 Forbidden (`forbidden`)
   - Reason: User's role (e.g. 'viewer') does not have write permission (`agent`+ required).
   - Solution: Disable send and edit buttons in UI when `account_role === 'viewer'`.

4. HTTP 429 Rate Limited (`rate_limited`)
   - Reason: Message send rate limit exceeded (120 requests/min).
   - Solution: Inspect `Retry-After` response header and queue outgoing messages.

5. Meta Cloud API Error 131047: 24-Hour Window Expired
   - Reason: Agent tried to send free-form text outside the 24-hour service window.
   - Solution: Catch error code 131047 and prompt the mobile user: "This conversation's 24-hour window has expired. Please send an approved Template to re-open it."

6. Media Upload Size Limits
   - Image: Max 5 MB
   - Video / Audio / Document: Max 16 MB
   - Solution: Mobile app should compress images and check file size before uploading to Supabase Storage.
